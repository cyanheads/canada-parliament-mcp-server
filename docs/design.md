# canada-parliament-mcp-server — Design

## MCP Surface

All eight tools are read-only, idempotent, and open-world: `{ readOnlyHint: true, idempotentHint: true, openWorldHint: true }`. No auth scopes, resources, prompts, Apps, SQL workspace, or persistent mirror. Tools alone cover the complete workflow.

| Tool | Capability | Main inputs |
|:---|:---|:---|
| `canparl_search_bills` | Find House and Senate bills in one parliamentary session | session, title filter, bill code, type, chamber, status, sponsor |
| `canparl_get_bill` | Read a bill dossier or page a selected section | session, billCode, section, offset, limit |
| `canparl_search_members` | Find current MPs, or search the historical politician index by name | name, riding, province, party, includeFormer |
| `canparl_get_member` | Read an MP profile, memberships, sponsored bills, and recent ballots | slug or personId; activity limits and offsets; votesSession, votesBillCode |
| `canparl_search_votes` | Find recorded House divisions | session, billCode, result, documentType, dates, subject filter |
| `canparl_get_vote` | Inspect one House division and its party and individual ballots | session, number, party, province, ballot, personId |
| `canparl_search_speeches` | Find House Hansard speeches by speaker, bill, date, and bounded text scan | politician, billDebated, mentionedBill, dates, contains |
| `canparl_list_reference` | Decode sessions and source-specific filter vocabulary | topic, optional session |

## Overview and requirements

Serve public-affairs analysts, legal researchers, journalists, and civic organizations tracing Canadian federal legislation, representation, recorded divisions, and legislative intent. LEGISinfo is authoritative for bicameral bills; OurCommons for the current House roster and recorded House divisions; OpenParliament supplies historical profiles and indexed House speeches and activity. Senators, standalone Senate proceedings, committees, and provincial legislatures are outside scope.

Public keyless GET requests only. Support Bun and Node through STDIO and Streamable HTTP with `sessionMode: 'stateless'`. No user round trips or durable personal-data store. Cache only parsed public responses in memory for short periods. This server is an accurate, unofficial relay; Parliament retains copyright. Credit Parliament and link OpenParliament where used. The [Parliament notices](https://www.parl.ca/ImportantNotices-e.html), [Speaker's Permission](https://www.ourcommons.ca/en/important-notices#SpeakersPermission), [Senate terms](https://sencanada.ca/en/intellectual-property/), and [OpenParliament API terms](https://openparliament.ca/api/) govern reuse. Preserve the noncommercial/free relay posture; do not claim an open-data licence or government endorsement.

## User goals

1. Find a bill by session, number, title, type, stage/status, or indexed MP sponsor; inspect its progress through both chambers.
2. Follow a bill's House division numbers into full tallies and individual ballots, and carry an enacted statute citation into a legal research workflow.
3. Resolve a current MP by name, riding, province, or caucus, then inspect the verified profile and recent activity; find former MPs by name.
4. Find House speeches on a bill, by an MP, or during a date range, preserving full returned speech text and honest scan coverage.

## Shared contracts

### Inputs and normalization

All input/output fields have `.describe()`. Use JSON-Schema-compatible Zod schemas, with strict nested objects. Trim optional strings; a blank is unset and never becomes an upstream `key=`. Validate semantic combinations in handlers after normalization; do not use schema transforms. All multi-filter searches use AND.

| Input | Canonical form and behavior |
|:---|:---|
| `session` | Optional string `P-S` or strict `{ parliament: positive integer, session: positive integer }`. Trim and canonicalize digits. Missing means current, resolved from the default LEGISinfo JSON feed, never a hardcoded session. No guessed session arithmetic. A string the schema admits but that names no positive safe-integer pair (`45-0`) fails with the tool's session reason, field-named like any other filter. |
| `billCode` / nested bill `code` | Normalize case, optional `Bill ` prefix, and at most one separator between chamber and number — a Unicode space separator or a dash (`-`, U+2010–U+2015, U+2212): `bill s321`, `S 321`, `S–321` → `S-321`. One trailing letter is part of the code: LEGISinfo and OpenParliament publish split bills beside their base code (37-1 `C-15A`/`C-15B`, 37-2 `C-10A`/`C-10B`, 38-1 `C-333A`, 40-3 `C-23A`/`C-23B`), so `c-15a` → `C-15A`. Require `^[CS]-[1-9][0-9]*[A-Z]?$` on input and in every upstream record; no substitution between chambers. `C - 15`, `15`, `C-015`, `C-15AB`, `C-15A1`, `C-15 A`, and a line break between parts are rejected. Case classes are explicit ASCII, so no Unicode case folding (Kelvin sign, long s) reaches a canonical code. The pattern's adjacent classes are disjoint, so matching stays linear on unbounded input. |
| slug | Lowercase bare OpenParliament slug, or exact `/politicians/<slug>/` path; accept that path from an HTTPS OpenParliament URL after verifying its origin. Extract the slug and construct the request afresh. Never slugify a name. Slugs include digit-only OpenParliament IDs (394 of 1,326 indexed politicians, e.g. `5724`), so the grammar keeps digits. A digit-only value equal to a current official personId, or its `/politicians/<digits>/` path or URL (`canparl_get_member` `slug`, `canparl_search_bills` `sponsor`, `canparl_search_speeches` `politician`), is read as that personId through the verified crosswalk in `canparl_get_member`: the roster is read before any OpenParliament request, and `/politicians/{personId}/` is never requested. Every other value keeps its OpenParliament meaning; a digit-only value whose returned profile carries a different canonical slug is the tool's not-found reason, not a malformed response. |
| `province` | Accept all 13 postal codes or full English province/territory names, case-insensitively; normalize to full name. Codes: AB Alberta, BC British Columbia, MB Manitoba, NB New Brunswick, NL Newfoundland and Labrador, NS Nova Scotia, NT Northwest Territories, NU Nunavut, ON Ontario, PE Prince Edward Island, QC Quebec, SK Saskatchewan, YT Yukon. `PQ` and fuzzy geographic names are rejected. |
| enum-like filters | Trim, case-fold, and normalize straight/curly apostrophes, Unicode composition, and repeated whitespace against the relevant vocabulary. Return canonical upstream spelling. Never use fuzzy matching or silently remove an unknown value. `House of Commons` → `House` is a certain chamber alias. |
| dates | Real Gregorian `YYYY-MM-DD`; reject invalid days or reversed bounds. Both bounds are optional independently. Match civil dates in Parliament's Ottawa time, not UTC. Preserve upstream date-time strings without inventing an offset, except bill `royalAssentDate` and `milestones`, which express the instants LEGISinfo publishes as UTC `YYYY-MM-DDTHH:MM:SS[.fraction]Z` (see `canparl_search_bills`). |
| local text filters | Case-insensitive literal substrings after Unicode normalization; title filter checks English/French long/short titles independently. Speech `contains` checks normalized English plain text. No query language or fuzzy ranking. |

A rejected filter value fails with the tool's declared filter reason. The message is `<field path>: Expected …`, naming every accepted value of a closed vocabulary (catalog labels, the selected feed's observed labels, then that field's aliases) or the expected shape of a code, slug, date, or session; `data.field` carries the path and `data.allowed` the listed values. Session-index misses (`unknown_session`, `unsupported_vote_session`, `unknown_reference_session`) list the source's session index the same way, and a malformed session token fails with the same reason, naming the expected shape. The rejected value is never repeated: the caller already holds it, filter strings carry no length bound, and the framework's own argument rejections do the same. Only a field-named rejection from a normalizer converts to a filter reason, with the normalizer error kept as `cause`; any other failure propagates unchanged. `normalizeFilter`, `rejectFilter`, `rejectSession`, and `filterFailure` in `src/domain/normalization.ts` are the one mechanism every filter uses.

Accept `query` as an alias for canonical `titleContains` on bill search and `subjectContains` on vote search, declared with `inputAliases`. Those canonical names make the local mechanic explicit; do not send `q` upstream. Current member `name`/`riding` are also local substring filters. Historical name semantics are specified separately below.

### Results, pagination, and rendering

Notation below is the exact domain output; `?` means optional, `T | null` means a known field whose value is unavailable. Do not replace missing data with false, zero, an empty name, or an invented identifier. Empty upstream collection means `[]`; omitted/null upstream collection becomes `null` where the output distinguishes unavailable from none. Required identity fields missing from a record are a malformed upstream response, not fabricated defaults.

Every tool returns `provenance: Source[]`, where `Source = { source: 'legisinfo' | 'ourcommons' | 'openparliament', url: string, retrievedAt: string, cached: boolean }`. A cached entry retains its original retrieval timestamp. Output links are absolute HTTPS URLs; relayed source URLs (bill web references, member profile links) are the stated exceptions. Source fetch URLs are provenance, never accepted as caller destinations. Every field named below is required unless marked `?`.

Common list inputs: `limit` integer 1–100 per call, default 25, and `offset` integer ≥0 default 0, unless a tool states otherwise. Every count input accepts values up to one shared ceiling of 10,000: the handler clamps a value above the tool's per-call cap to that cap before any upstream call, enrichment `cap` and `pagination.limit` carry the effective value, and a notice names the requested and effective values (no notice at or below the cap). Values above 10,000 or below a minimum stay invalid arguments. Common local pagination output: `{ offset, limit, nextOffset: integer | null, hasMore: boolean }`, where `limit` is the effective value. Fetch and filter the complete bounded session/roster before slicing. `total` is the exact filtered count before slicing. Sort bills by chamber prefix, then number, then split-bill suffix (`C-15` < `C-15A` < `C-15B` < `C-16`); current MPs by surname, given name, personId; divisions by date-time descending then division number descending; ballots by party, surname, given name, personId. No mutable server cursor state.

Zero, under-cap, exactly full, and past-end are explicit: zero → empty array, total 0, no continuation; under-cap → no continuation; full → continuation only if more rows exist; past-end → empty array, unchanged exact total, no continuation and guidance to restart at offset 0. Offsets describe the selected ordering, and upstream changes can shift later pages; no snapshot guarantee. For OpenParliament lists without counts, `total: null`; `hasMore`/continuation derive from `pagination.next_url`, never from `length === limit` alone. Validate that each next URL belongs to the same API origin, endpoint, filters, and a strictly increasing offset; reconstruct its allowlisted request rather than fetching an arbitrary link.

Declare per-tool enrichment for normalized `appliedFilters`, optional `notice`, and cap disclosure (`shown`, `cap`, `truncated`). Current bill, member, and division searches and `canparl_get_vote` set exact `totalCount` directly in measured enrichment; historical member search omits it, and speech search has no exact count. Domain totals below remain in output because they define the collection. Populate required enrichment on every success path; budgeted tools render every enrichment field through `measuredTrailer`. A continuation is not an instruction to change filters. `truncated` means more of the queried collection remains; speech scan exhaustion is separately disclosed.

`canparl_get_bill`, `canparl_get_vote`, and all four search tools share one 24,000-byte complete-response budget (`RESPONSE_BUDGET`) and one measure (`responseBytes`, both in `_format.ts`): the UTF-8 JSON-RPC response with 256 bytes reserved for the request ID, `structuredContent` with enrichment merged, and `content[]` with its enrichment trailer. The measure includes final notices and equals the wire because these tools render every enrichment field through `renderValue` (`measuredTrailer`). Pages hold whole records in order and stop before the record that would exceed the budget, returning at least one when records exist; a stop sets `truncated: true` and a notice naming the budget and count returned, with any clamp notice first. A single oversized record returns whole with disclosure. Exact current totals and effective count limits remain unchanged. For the three list searches, continuation advances by delivered rows when the budget shortens a page. A fully delivered historical member page preserves the validated upstream `nextOffset`, including gaps or null; a shortened historical page resumes at input offset plus delivered rows so omitted rows remain reachable.

`format()` renders the full schema recursively with explicit field labels, all rows, all nested stage/activity values, null markers, booleans, and pagination. No display-only caps. Every field is one `key: value` line in a blockquote. A non-empty container line (`key: [object]`, `key: [array]`; empty ones render `{}` and `[]`) is followed by its fields one quote level deeper, array items keyed by index; sibling lines share a paragraph joined by backslash hard breaks, and a bare quote line at the shallower depth closes the deeper levels. Result root fields open at depth 1 with no wrapper line. Nesting carries structure because every CommonMark parser recovers it from blockquote depth at about the byte cost of a flat rendering; path-qualified keys cost about 60% more bytes on bill stages and halve `canparl_get_bill` stage pages, and child counts force a reader to count lines to find where a record ends.

Encode each key and string value in one pass: backslash-escape ``\ ` * _ ~ [ ] < &`` everywhere, and encode CR, LF, and Unicode whitespace at either end of the string as numeric character references (`&#13;`, `&#10;`, `&#32;`, `&#160;`). A key opens a line, so it also escapes a leading ASCII punctuation character and the `.` or `)` after a leading digit run; a value follows `key: ` mid-line and needs no block guard. Internal spaces, tabs, and other Unicode characters stay literal. An internal space cannot open a block; references for line breaks and edge whitespace become text only after block parsing, so no value can forge a heading, fence, list, table, or HTML block, and parsers that trim paragraph edges (commonmark.js trims all Unicode whitespace) lose nothing. Line breaks inside a value are always references, never literal newlines or hard breaks, which do not preserve raw line endings. The parsed CommonMark text then contains the original value directly, including CR/LF distinctions, blank lines, leading/trailing whitespace, and fence-looking content.

Scalar types survive in the text. A string value that would read as a JSON number, `true`, `false`, `null`, or a container marker, or that opens with `"`, renders as a JSON string literal (`"200"` beside the number `200`); so does a key containing `: ` or opening with `"`. A line therefore splits at a leading JSON key literal, else at the first `: `, else at a final `:` that marks an empty string. Reject upstream strings containing NUL or unpaired UTF-16 surrogates as malformed upstream text: CommonMark cannot represent these values exactly, so never silently replace them. Never inject raw upstream HTML or external prose into headings/labels.

Link values render as `[url](<url>)`, image values as `![imageUrl](<imageUrl>)`, with the exact URL recoverable from parsed destination and label/alt text; escape labels with the same text encoder and destinations without changing the decoded value. If an unusual URL needs an encoded destination for CommonMark validity, include its exact original value as an encoded text node alongside the rendered link/image. Unknown fields and keys in retained JSON records use the same recursive renderer. Structured enrichment uses it through `enrichmentTrailer.render`. Filter-validation messages list accepted labels in plain text, one identical string on both surfaces, with the exact array in `data.allowed`; every observed source label is free of CommonMark-active characters. Other domain error messages use fixed prose and keep variable source values in structured data rather than interpolating them into a lossy trailer. Contract tests decode `content[]` structurally (blockquote depth and hard breaks from `Bun.markdown.html`) back into the `structuredContent` value, comparing keys, key order, arrays versus objects, scalar types, CR/LF sequences, and link/image destinations; the adversarial key, value, and standalone-string corpus also runs through the CommonMark reference implementation.

### Session and vocabulary discovery

Use the actual LEGISinfo `/legisinfo/en/bills` session picker (`data-input="parlsession"`) and OurCommons `/Members/en/votes` picker (`data-input="parlSession"`); discard the non-session `all` option. Cache indexes six hours. The default LEGISinfo JSON feed identifies current through its actual `(ParliamentNumber, SessionNumber, IsSessionOngoing)` rows. Require one consistent current session; an empty or contradictory default is upstream failure. New current sessions augment a stale index only when returned and verified by that source, never by incrementing numbers.

The verified LEGISinfo index contains `35-1`, `35-2`, `36-1`, `36-2`, `37-1`, `37-2`, `37-3`, `38-1`, `39-1`, `39-2`, `40-1`, `40-2`, `40-3`, `41-1`, `41-2`, `42-1`, `43-1`, `43-2`, `44-1`, `45-1`. Its [help](https://www.parl.ca/legisinfo/en/help) distinguishes essential bill data for 35th/36th Parliaments from full dossiers beginning 37-1. OurCommons divisions picker begins 38-1 and contains the subsequent sessions in that list. OpenParliament documents politicians since 1994; do not assert that every session has every indexed bill, ballot, or speech. Its `/sessions/` endpoint does not exist. Reference coverage distinguishes `advertised`, `basic`, `full`, and `not_supported`, rather than asserting exhaustive record availability.

Status/type vocabulary is a bundled, documented catalog supplemented by the selected official session feed's distinct nonblank labels; historical labels and future new labels must remain usable. A recognized label with zero matching rows is empty success, never an invalid-value error. Current reference topics expose observed labels and catalog labels with their applicability. Party names are likewise source-specific: OurCommons uses `Bloc Québécois`/`Green Party`; OpenParliament may use `Bloc`/`Green`. Preserve raw source names in profiles/activity; normalize `Bloc`→`Bloc Québécois` and `Green`→`Green Party` only at official-filter boundaries. Validate a historical ballot-party filter against the full division's observed caucuses as well as catalog labels, never only today's caucuses.

## Tools — detail

All error tables specify literal inline definition contracts. Codes below are `JsonRpcErrorCode` members. `retryable` is false unless stated; source-origin errors carry `thrownBy: 'service'`. Ordinary network, 5xx, timeout, cancellation, and parse failures keep framework baseline codes; do not repeat those in every domain table. Valid detail identifiers missing from an upstream are typed not-found failures; collection searches with no rows are successes.

All eight tools additionally declare `upstream_blocked` (`ServiceUnavailable`, `retryable: false`, `thrownBy: 'service'`) for an official source's HTTP 403 refusal. The service names LEGISinfo or OurCommons, returns `status: 403` and its source identifier, and supplies a source-specific recovery hint to retry later for official parliamentary data. No response body reaches the client; both official fetch boundaries disable framework error-body capture before logging. Refusals are neither retried nor cached and never broaden a query, bypass a restriction, or substitute third-party data. Optional enrichment retains its unavailable-section behavior and fixed public failure classifications. Source restrictions are operational conditions; their cause is not inferred from a refusal.

### `canparl_search_bills`

Description: “Find House and Senate bills in one session by title, number, type, chamber, status, or indexed MP sponsor. Sponsor results are the OpenParliament-indexed subset; fetch a bill for its sponsor, stages, divisions, and statute citation. Omitted session means the verified current official session. Follow nextOffset with identical filters.”

| Parameter | Type/default | Mapping |
|:---|:---|:---|
| session | shared optional | LEGISinfo `parlsession` |
| titleContains, billCode | optional strings | local titles / exact normalized code |
| originatingChamber | optional House or Senate | reconcile name, explicit chamber flags, organization ID |
| billType, status | optional vocabulary strings | local `BillDocumentTypeNameEn`, `StatusNameEn` |
| sponsor | optional slug, or a current MP's personId | OpenParliament `sponsor_politician=/politicians/<slug>/` plus `session`, using the verified profile's slug |
| limit, offset | shared | local after all filters |

Fetch official whole-session JSON. Its payload is an array even for a single bill. List sponsor fields contain whitespace placeholders and statute fields may be null; neither is exposed in bill rows. `BillSummary = { session, billCode, longTitle: { en: string | null, fr: string | null }, shortTitle: { en: string | null, fr: string | null }, billType: string | null, originatingChamber: 'House' | 'Senate' | null, status: string | null, latestMajorStage: { name: string | null, chamber: 'House' | 'Senate' | null } | null, royalAssentDate: string | null, url }`. Map major stage from `LatestCompletedMajorStageNameEn` and its chamber, not from latest minor event. The list feed leaves `LatestCompletedMajorStageChamberNameEn` null and publishes only `LatestCompletedMajorStageChamberOrganizationId` (always 1 or 2; royal assent is 2), while the dossier also names the chamber, so the major-stage chamber goes through the same reconciler as the originating chamber and both tools report `House` or `Senate`. `latestMajorStage` is null only when both its name and chamber are absent. `royalAssentDate` uses one representation on both tools, a UTC instant `YYYY-MM-DDTHH:MM:SS[.fraction]Z`: the list publishes `ReceivedRoyalAssentDateTime` with an Ottawa offset (`2026-03-26T06:50:00-04:00`) and converts to its instant, while the dossier publishes the same instant as an offset-less UTC clock (`2026-03-26T10:50:00`) and gains `Z`. Fraction digits are kept as published, so both feeds yield the same string, and a date-only value (midnight UTC) keeps its calendar date instead of landing on the previous Ottawa evening. An offset-less list value has no stated zone; it and any value in neither shape are relayed as published rather than failing the list.

Output: `{ session, total, bills: BillSummary[], pagination, sponsorCoverage: 'not_applied' | 'openparliament_index', provenance }`. With sponsor, resolve one verified profile (a slug's own profile, or the crosswalk for a current personId; see the slug row under Inputs and normalization), fetch all matching OpenParliament bill pages (100/page, at most 10 pages), then intersect exact `(session, number)` keys with the official set before local filters and slicing. No per-bill profile/detail scans. If the sponsor scan has a next page after its bound, fail rather than report a false complete total. Always disclose that OpenParliament indexing may lag and does not index Senators as politicians; this filter cannot prove absence of an official sponsor's bills.

`appliedFilters.sponsor` echoes the verified profile's slug and `appliedFilters.sponsorName` its name (null without a sponsor), so a personId reading or a numeric OpenParliament ID shows whom it named. Every sponsor continuation retains the requested session and sponsor; verify each returned session equals the requested session. Consume through null next_url before reporting total, even if the requested local page is already full. Deadline exhaustion is Timeout, never a partial sponsor intersection presented with an exact total.

| reason | code | when | recovery |
|:---|:---|:---|:---|
| unknown_session | ValidationError | session malformed or absent from LEGISinfo index | Call canparl_list_reference with topic sessions and choose a listed bill session. |
| invalid_bill_filter | ValidationError | invalid code/chamber/sponsor slug or unrecognized type/status | Retry canparl_search_bills with a value or shape the error names; canparl_list_reference topics bill_types and bill_statuses list types and statuses, and a sponsor is member.slug from canparl_get_member, a slug from an includeFormer canparl_search_members row, or a current MP's personId. |
| sponsor_not_found | NotFound | slug has no profile of its own, or a current personId has no unique verified profile | Call canparl_search_members with includeFormer true and a surname or full name, then pass a returned slug as sponsor. |
| sponsor_scan_incomplete | ServiceUnavailable | 1,000 indexed sponsor rows consumed and more remain; nonretryable | Call canparl_search_bills without sponsor and inspect a specific result with canparl_get_bill. |

Empty notice fragments: no matches → “No bills matched the applied filters; remove titleContains, status, or billType and retry canparl_search_bills.” Sponsor applied → “Sponsor coverage is limited to OpenParliament's index, which may lag and does not index Senators as politicians; use canparl_search_bills without sponsor and canparl_get_bill to check official sponsors.” Past-end → “This offset is past the matching bills; retry canparl_search_bills with offset 0.”

### `canparl_get_bill`

Description: “Read one House or Senate bill's official dossier. Large dossiers return an outline; re-call with one section and follow pagination.nextOffset for collections. Stages preserve nested records whole. Obtain billCode and session from canparl_search_bills; omitted session means the verified current official session.”

Inputs: shared `session` optional; `billCode` required. GET `/legisinfo/en/bill/{session}/{lowercase-code}/json`; require exactly one matching record. A bill ErrorPage redirect containing `StatusCode=404` is missing, even when automatic redirects would finish at 200 HTML. Inspect redirects manually before following; never retry that missing record as a JSON outage.

Optional `section` selects one of 14 sections: the collections `stages.house`, `stages.senate`, `stages.royalAssent`, `divisions`, `senateVoteDetails`, `publications`, and `webReferences`, or the scalars `sponsor`, `statute`, `summary.en`, `summary.fr`, `notes.en`, `notes.fr`, and `milestones`. Collections accept `offset` (default 0) and `limit` (default 20, per-call maximum 100; values up to 10,000 clamp to 100, disclosed through `pagination.limit` and a notice that counts toward the 24,000-byte budget). Nondefault pagination without a collection selector is rejected, whatever its size, and an unknown selector's error lists all 14 names. Unselected responses retain the full output below; when the complete UTF-8 serialized response exceeds 24,000 bytes, return `{ kind: 'outline', bill, sponsor, statute, milestones, provenance, sections: [{ name, count }], disclosure }` instead. The inline `sponsor`, `statute`, and `milestones` answer who sponsored the bill, its citation, and how far it has read without a second call; the largest of 42 sampled outlines is 5,840 bytes (45-1 C-219). Measurement includes the actual recursive formatter, explicit enrichment renderers, both consumption surfaces, and a JSON-RPC envelope with 256 bytes reserved for the request ID.

Selections return `{ kind: 'section', bill, provenance, [selected field], totalCount, pagination: { section, offset, limit, total, nextOffset }, disclosure? }`. A dotted selector keeps its parent key and only the selected child: `stages.house` returns `{ stages: { house } }` and `summary.en` returns `{ summary: { en } }`. Summaries and notes split by language because a single language already reaches 60,676 bytes on the wire in English and 72,626 in French (44-1 C-69), so one bilingual section would double that; paging by paragraph was rejected because single summary paragraphs reach 26.9 KB. An oversized language section takes the whole-with-disclosure path. Scalar and unavailable sections have null totals. Reduce collection pages by whole records until the serialized response fits; preserve every nested field. A single indivisible record or scalar that cannot fit returns whole with explicit disclosure. A page the budget shortens below the effective limit discloses “The 24000-byte response budget ended this page after N records; call canparl_get_bill with pagination.nextOffset and the same section to continue.”, measured inside the budget. Empty, unavailable, and past-end pages are explicit; following `nextOffset` reconstructs the collection. This keeps expensive dossiers navigable without silently losing parliamentary records.

One chamber reconciler serves `originatingChamber` and `latestMajorStage.chamber`. It maps the official name (`House of Commons`/`House`/`Senate`) and organization ID (1 House, 2 Senate) to `House` or `Senate`; for the originating chamber it also takes positive `IsHouseBill`/`IsSenateBill` flags. Contradictory evidence, an unknown name or ID, or a false flag for an otherwise identified chamber fails as an invalid upstream response. Absent evidence stays null; bill-code prefixes never determine chamber.

Output: `{ bill: BillSummary, sponsor: { name: string | null, personId: string | null, riding: string | null, title: { en: string | null, fr: string | null } }, stages: { house: Stage[] | null, senate: Stage[] | null, royalAssent: Stage[] | null }, divisions: BillDivision[] | null, senateVoteDetails: JsonRecord[] | null, publications: Publication[] | null, statute: { year: integer, chapter: string, citation: string } | null, summary: { en?: string | null, fr?: string | null }, notes: { en?: string | null, fr?: string | null }, milestones: Milestones, webReferences: WebReference[] | null, provenance }`. The full dossier carries both languages of `summary` and `notes`; a language section carries one.

`sponsor.title` maps `SponsorAffiliationTitleEn/Fr` (a ministerial office, `Senator`, or `Member of Parliament`; blank on 35th-Parliament records). `summary` maps the Library of Parliament `ShortLegislativeSummaryEn/Fr` and `notes` maps `NotesEn/Fr`. Both convert HTML to plain text with the shared `src/domain/` converter the speech parser uses, in a mode that keeps each anchor's target as `text (href)`: notes link Senate committee pages, and dropping the `href` would lose them. Speech text keeps dropping link targets. Summaries carry only `<div>` and `<br>`; notes add `<p>`, `<b>`, `<sup>`, and `<a href>`. Each block ends its paragraph, and a block's first visible character starts a new one unless a line break already precedes it: 44-1 C-2 notes open a `<p>` straight after inline text (`the following motion:<p>That`), which would otherwise run together. An empty, whitespace-only, or break-led block adds no second separator. A null or blank source value, or markup with no text, is null.

`Milestones = { houseFirstReading, houseSecondReading, houseThirdReading, senateFirstReading, senateSecondReading, senateThirdReading }`, each `string | null`, mapped from `Passed{House,Senate}{First,Second,Third}ReadingDateTime`. The dossier publishes these as offset-less UTC clocks, so they take `royalAssentDate`'s representation, a UTC instant `YYYY-MM-DDTHH:MM:SS[.fraction]Z`; a value in another shape is relayed as published. Royal assent stays `bill.royalAssentDate`. Senate times of day are unreliable at the source (a 10:15 UTC first reading is 05:15 in Ottawa), and date-only values are midnight UTC.

The scan measures each match as the page would return if a budget stop ended it there. A match that does not fit is not consumed: `scanned` stops at it, `excludedCommittees` counts the same range, `nextOffset = input.offset + scanned` points at it, `exhausted` is false, and no further candidate page is fetched. If candidates scanned since the last returned speech (later pages, exclusions) push even that page over, the page ends right after the last returned speech instead, so the continuation revisits those candidates. A first match that exceeds the budget alone returns whole and ends the page. Memberships are fetched after the scan, in page order; a speech whose hydrated affiliation no longer fits ends the page before it, on the same terms. Memberships are fetched for returned speeches plus at most the one that did not fit; provenance lists the scan's retrievals up to the page's end, then the returned speeches' memberships.

Output `{ speeches: Speech[], scanned: integer, exhausted: boolean, nextOffset: integer | null, provenance }`. `Speech = { id: string, speaker: string | null, politician: string | null, membershipUrl: string | null, party: string | null, riding: string | null, time: string, h1: string | null, h2: string | null, content: string | null, procedural: boolean | null, url, debateUrl: string | null }`. Map source_id/url for identity; attribution.en for speaker; h1/h2 can be omitted; politician may be absent for institutional speakers. Convert content.en HTML to plain text with paragraph/line breaks and entities preserved, no summarization, no text-length truncation. A genuinely missing English body is null and cannot match contains. Fetch each distinct `politician_membership_url` of a returned speech, plus at most the one match that did not fit (maximum ten), for party/riding at the speech date; never substitute the member's current affiliation. Missing membership is null with an explicit unavailable enrichment notice; transient failure of optional membership enrichment also preserves speeches with a notice, but never suppresses caller cancellation. No profile scan per raw candidate.

Every service method takes a final request context carrying signal and the remaining call budget; all return parsed production types plus provenance. LEGISinfo: `getSessions`, `getCurrentSession`, `listBills(session)`, `getBill(session, billCode)`. OurCommons: `getVoteSessions`, `listMembers`, `listVotes(session)`, `getVoteParticipants(session, number)`, `listMemberVotes(personId, session?)`. OpenParliament: `listPoliticians({ include, name?, familyName?, limit, offset })`, `getPolitician(slug)`, `listBills({ session?, sponsor, limit, offset })`, `getBill(session, billCode)`, `listBallots({ politician, limit, offset })`, `getVote(session, number)`, `listSpeeches({ politician?, billDebated?, mentionedBill?, dateFrom?, dateTo?, substantiveOnly, limit, offset })`, `getMembership(path)`. Pagination responses expose parsed objects and a validated next offset; tools never parse arbitrary hypertext URLs themselves. Use `initLegisinfoService`/`getLegisinfoService` and equivalent OurCommons/OpenParliament init/accessor names.

The gaps on official feeds are conservative client policy, not advertised rate limits. OpenParliament documents concurrent-request throttling but no numeric quota. Each tool additionally has one 50 s total call deadline covering all composed calls, queue waits, retries, body reads, and hydration. Thread a composed signal through each service; retries cannot restart the tool's 50 s clock. A service operation receives remaining time and uses `deadlineMs = min(20_000, remaining)`; attempt timeout `min(10_000, attempt.remainingMs)`. `withRetry` surrounds pacer.run and the entire fetch→read→parse→validate pipeline; every attempt uses its own signal. Honor Retry-After through framework primitives. Dispose pacers in teardown. Cancellation wins over optional-section degradation.

Budget all upstream work to a 45 s subdeadline, reserving the remaining 5 s for normalization, rendering, and framework return. Do not promise every advertised maximum completes under arbitrary latency. A current-person crosswalk requires at most six OpenParliament requests (one exact-name page, two surname spellings, three profiles); an ordinary exact success stays one name page and one profile. With a cold cache and no retry, personId member lookup can require 12 OpenParliament operations (six identity requests, one sponsored-bill page, five bill details), hence at least 22 s between request starts, and so does a slug that is a current personId; their ballots are one OurCommons member-votes request outside that pacer (two OurCommons requests with the roster, three when `votesSession` adds the divisions picker). A slug whose profile carries one official personId needs at most 7 (12 s); any other slug lookup reads OpenParliament ballots and needs at most 18 (one profile, two activity pages, five bill details, ten vote details: 34 s). Sponsor search needs at most 16 for a current personId (six identity requests, ten sponsor pages: 30 s) and 11 for a slug (20 s); speech search needs at most 23 for a current personId (six identity requests, two bill validations, five pages, ten membership details: 44 s) and 18 for a slug (34 s). A digit-only slug input adds one OurCommons roster read, cached five minutes like every roster read and outside the OpenParliament pacer. These are pacing lower bounds, not completion estimates; queue competition and retries consume the same budget.

Required fetch/scan exhaustion fails with Timeout, preserving the completeness guarantees. Optional crosswalk, activity, and speech-membership work receives a child signal limited by the 45 s subdeadline. When only that child deadline expires and the caller is still active, stop queued work and return the already obtained official profile or speeches with explicit unavailable enrichment. An activity section whose page or detail hydration is incomplete is wholly unavailable, has no misleading empty-history continuation, and retains the caller's requested offset and the effective limit. Budget exhaustion in one optional section prevents starting later uncached enrichment; mark it unavailable with Timeout metadata too. A caller abort or the outer 50 s deadline always fails the call and is never treated as optional degradation. Tests cover cold maximum counts, queue contention, retries, child-budget expiry, and outer cancellation with fake time.

Use framework `withRetry`, `createPacer`, `fetchWithTimeout`, error factories, and parsing utilities where they fit. XML parsing must disable entity expansion/external entities and preserve singleton/empty arrays and `xsi:nil`. Normalize number/boolean scalars explicitly; reject malformed required numbers instead of coercing blank to zero. No SDK is necessary for three small HTTP surfaces. Production parsing uses `fast-xml-parser` for XML and `linkedom` for HTML session pickers. Parse HTML session pickers as data with exact selectors and validated tokens; no executable scripts.

Only fixed HTTPS origins `www.parl.ca`, `www.ourcommons.ca`, and `api.openparliament.ca` are request destinations. Build paths from validated identifiers with URL APIs and strict per-method parameter allowlists. No generic URL/base-URL config. For LEGISinfo manually handle `fetchWithTimeout`'s non-2xx McpError under `redirect: 'manual', errorHeaders: ['location']`: classify the known 404 ErrorPage before any follow; approve only same-origin expected canonical redirects (maximum three). Do not combine a manual-origin policy with automatic redirect following. Other services likewise reject cross-origin redirects and unexpected API paths. Never fetch profile links, publication URLs, or image URLs merely because they appear in data. Unexpected 200 HTML is transient ServiceUnavailable, retried within the fixed budget; deterministic schema mismatches are nonretryable upstream-response failures. No failure caches and no stale-on-error substitution.

## Workflow analysis and decisions

Bill research is official session search → official dossier → official House division, or an enacted statute citation. Sponsor search adds one profile validation (the bounded crosswalk for a current personId) and a bounded complete OpenParliament ID-set scan before official intersection; it does not replace the official bill result with third-party metadata. MP research is official roster → verified individual crosswalk → bounded independently pageable activity; a member's official ballots for a session come from one member-votes request, filterable by bill, and full-profile hydration adds at most five bill detail requests, plus ten vote detail requests only for a member without one official personId, preserving source vocabulary. Official ballots replaced per-row OpenParliament hydration because that path cost eleven paced requests for ten rows, could lag the official record, and could not answer how a member voted on one bill. Speech research scans at most five candidate pages and hydrates only the membership URLs of returned speeches plus at most one that did not fit, at most ten, inside the same deadline.

One 24,000-byte response budget and one measure serve every tool that pages large records. Hansard speeches run from tens of characters to over 16,000, so a lower count cannot bound them, and a second, larger figure for ballots would leave two budgets in one server; `canparl_get_vote`'s default limit dropped to 30 instead. Speech memberships hydrate after the scan rather than inside it: a slow membership lookup is optional enrichment and must not spend the 45-second budget that required candidate pages need, so it leaves affiliation unavailable instead of failing the call. The scan measures speeches before their affiliation is known, so a page can occasionally fetch one candidate page past where the hydrated page ends.

Count inputs above a per-call cap clamp instead of failing: every tool is a read with a continuation, so the capped page plus `nextOffset` loses nothing, while a rejection only costs the caller a round trip. The shared 10,000 ceiling sits above every collection one call pages (the largest session bill list holds 575 bills), so it separates large requests from garbage without rejecting any real one.

A digit-only slug input that equals a current personId, bare or as its `/politicians/<digits>/` path or URL, is read as the personId, because no current personId equals an indexed numeric OpenParliament path (0 of 337 on 2026-10-20: current personIds reach six digits, indexed numeric paths stop at 8,188), so that precedence costs no real slug, while the OpenParliament record at a personId's numeric path is another politician, a slugged profile, or missing. The crosswalk stays roster-only, so a former member's personId keeps its OpenParliament meaning; the name echoed in `appliedFilters` exposes any mismatch. Rejected: dedicated `sponsorPersonId`/`politicianPersonId` inputs (they still need the same roster check to stop a personId pasted into `sponsor`), and a guard fetch of `/politicians/<digits>/` to detect a value that is both (a paced request on every personId resolution, for an empty set).

The roster cannot supply a verified slug, and OpenParliament's historical index cannot supply full membership fields. Current rows therefore chain through personId and historical rows through slug, with nulls explicit. This preserves complete official roster search without N+1 scans or name-derived identity claims. Unsupported historical geographic/party filtering is rejected because applying it to sparse current-page rows would exclude valid history without evidence.

The two official sources' session pickers are necessary because unknown-session requests can return plausible empty success. Coverage is source-specific and basic pre-2001 bill data is intentionally available with honest nulls. Null/sparse stages, absent English speech text, non-MP speakers, indexed sponsor gaps, no nonvoter rows, publication redirects, and unavailable OpenParliament identity matches remain visible limitations. Preserve source-specific SenateVoteDetails JSON records without imposing a House-compatible schema or adding a Senate vote tool.
